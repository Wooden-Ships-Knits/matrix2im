# matrix2im Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tool Python `matrix2im` (CLI + library) yang membaca F27 MATRIX MASTER (.xlsx) dan menghasilkan raw JSON (Tahap 1) serta final JSON per colorway + `needs_review` (Tahap 2), identik dengan file golden.

**Architecture:** Tahap 1 (`extract.py`) membaca workbook dua kali (format + `data_only`), menemukan halaman/kartu/garis berdasarkan label dan warna, dan menyimpan hasilnya sebagai dataclass `Card` (termasuk nomor halaman untuk test). Proyeksi ke raw JSON terpisah (`to_raw_json`). Tahap 2 (`transform.py`) murni dict→dict, memakai aturan di `tag_rules.py` dan `whs_rules.py` yang mengembalikan `(nilai, Problem|None)`. Semua konstanta yang bisa berubah ada di `legend_config.py`.

**Tech Stack:** Python 3.11+ (venv dengan `/opt/homebrew/bin/python3.12`; `python3` sistem = 3.9 sehingga tidak dipakai), openpyxl 3.1.x, pytest, argparse, setuptools.

**Spec:** `PROMPT_CLAUDE_CODE.md` (instruksi kerja, aturan wajib, kriteria penerimaan) dan `docs/PRD_MATRIX_MASTER_to_IM_JSON.md` (sumber kebenaran aturan bisnis). Prototipe acuan perilaku: `reference/prototype/*.py`. Golden: `reference/golden/*.json`.

## Global Constraints

- Python `>=3.11`; dependensi runtime hanya `openpyxl`; dev hanya `pytest`. CLI pakai `argparse`. **Jangan pasang Pillow** (tanpa Pillow openpyxl melewati 220 foto; prototipe Tahap 1 = 0,9 detik).
- Entry point `matrix2im = "matrix_to_im.cli:main"` di `pyproject.toml`.
- Tidak ada nomor baris/kolom MATRIX yang di-hardcode (termasuk offset relatif halaman seperti `top+5`).
- Konstanta yang bisa berubah (warna legend, label, alias, prefix benang, regex) hanya di `matrix_to_im/legend_config.py`.
- Workbook input tidak pernah di-`save()`; file di `data/` tidak diubah, tidak di-commit.
- JSON: UTF-8, `ensure_ascii=False`, `indent=2`. Log ke stderr.
- Pesan error, warning, dan teks `issue` dalam Bahasa Indonesia; key dan kode persis seperti spec.
- Exit code: `0` sukses; `1` error fatal (termasuk validasi gagal); `2` hanya dengan `--strict` dan `needs_review` tidak kosong.
- Deterministik (selain `generated`); waktu `run` F27 ≤ 15 detik.
- Type hints di semua fungsi publik; docstring singkat yang menjelaskan *kenapa* aturan itu ada.
- Open issues (PROMPT §11) tetap `null` + `needs_review`; tidak ada aturan baru untuk kasus itu.

## Keputusan dan perbedaan PRD vs prototipe

Prototipe dijalankan pada `data/` dan hasilnya **identik** dengan kedua golden (styles, warnings, records, needs_review). Setiap perbedaan di bawah sudah diuji: memakai aturan PRD/PROMPT **tidak mengubah** output F27.

| # | Topik | Prototipe | PRD / PROMPT | Keputusan |
| --- | --- | --- | --- | --- |
| D1 | Gaya border garis merah | semua gaya (termasuk thin) | medium/thick/double | ikuti PRD |
| D2 | Pemecahan yarns | bagian ≥ 60 karakter yang mengandung `/` tidak dipecah | selalu pecah dengan `/` dan baris baru | ikuti PRD (heuristik 60 karakter tidak pernah terpicu di F27) |
| D3 | Awal pencarian baris NEW/nomor | offset tetap `top+6` / `top+5` | tanpa hardcode; nomor "di bawah legend" | NEW dicari dari awal halaman; nomor dicari setelah baris legend terakhir (baris yang punya sel berisi label legend dari config) |
| D4 | Akhir area warna | baris `- LEBAR/WIDTH` | PRD: "baris L: … cm" | sama di F27 (baris `L:` = baris LEBAR/WIDTH di 30 halaman); pakai LEBAR/WIDTH |
| D5 | Sel tanda baca | regex umum `[\W_]+` | PROMPT: `.`, `` ` ``, `*` | pakai regex umum (PRD: "hanya berisi tanda baca") |
| D6 | Baris baru di dalam sel TAG | `\n\n` → ` \| `, `\n` → spasi | tidak diatur | pertahankan (golden bergantung padanya) |
| D7 | Kapitalisasi WS TAG COLOR | seluruh TAG di-uppercase | hanya nama warna | pertahankan (golden) |
| D8 | Kartu tanpa nomor | tidak ada warning | PRD: harus masuk `warnings` | tambah warning (F27: 0 kasus) |
| D9 | Font tidak dikenal | `? (<kode>)` tanpa warning | `? (<kode>)` + warning | tambah warning (F27: 0 kasus) |
| D10 | Sel `TAG…` di area warna | dibuang diam-diam | tidak dihitung sebagai colorway | **usulan:** tidak jadi colorway, tapi dicatat sebagai warning (F27: 0 kasus) supaya instruksi tidak hilang diam-diam |
| D11 | Warna garis hitam | auto, indexed 8/64, theme 1, `FF000000`, `00000000` | PRD: indexed 64; PROMPT: 8/64 | pakai set prototipe (semuanya "hitam") |
| D12 | Deteksi record dobel | kunci (DESCRIPTION, colorway) tanpa cek sheet | "muncul di dua sheet" | kunci sama; kode `DUPLICATE_STYLE_ACROSS_SHEETS`; field tambahan `whs_values` |
| D13 | Nama file data | — | `data/F27_MATRIX_MASTER.xlsx` | file sebenarnya `data/Copy of F27 MATRIX MASTER.xlsx`; test mencari via env var → nama spec → glob `data/*F27*MATRIX*MASTER*.xlsx` (tanpa rename) |
| D14 | Tinggi halaman | — | 63–71 baris | sebenarnya 58–71; tidak berpengaruh karena tanpa hardcode |
| D15 | Garis hitam di baris warna pertama | dicari mulai `start+1` | tidak diatur | pertahankan (`start` vs `start+1` sama di F27) |
